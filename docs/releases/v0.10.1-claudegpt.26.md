# ClaudeGPT Reframe 0.10.1-claudegpt.26

Two fixes, and the content of 0.10.1-claudegpt.25, which was not released on its own.

- **A session stays in the folder it was launched in.** Claude Code's hooks report the folder the model is currently
  in, which changes when it `cd`s in a Bash command, and Reframe took that as the session's folder. The session then
  moved to another workspace in the list (one named after the subfolder, such as "src"), and resuming it from there
  could miss its transcript, which Claude Code keeps under the launch folder. A reported folder now becomes the
  session's only for a session without one, or for a worktree session moving into the worktree Claude Code made for
  it. Sessions already moved are set back on start: when the session's transcript is not under its folder's project,
  the `cwd` of the transcript's first entries (in the project folder of that `cwd`) is its launch folder, and the
  session's folder is set back to it only if the folder lies inside it. Each repair is logged.
- **Quitting no longer crashes intermittently with 0xC000041D.** Reframe follows other apps' windows through window
  event hooks whose native callbacks call into JavaScript from the message loop. They were never removed, so an
  event arriving while Electron tore down after the last quit (another app's, or another Reframe's, window appearing)
  could end the process with a fatal exception in a user callback. The hooks are now removed when quitting begins,
  and an exception in their callbacks is contained. This mechanism is inferred from the code and from when the crash
  happened (a second Reframe started with `--quit` while the first quits); it is not confirmed by a crash dump.

From 0.10.1-claudegpt.25 — PTY host protocol additions for the experimental native WPF shell (`wpf/`), additive and
advertised, protocol version unchanged (1):

- **Observers**: a client can attach read-only beside Reframe (`role: "observer"`, advertised as
  `services.observer: 1` and `observer: 1` in the host descriptor), with read-only terminal views and read-only
  services; other requests get the error code `forbidden`. `observer.primary` tells whether Reframe is attached.
- **Ordered session statuses**: `sessions.status` events and `sessions.list` carry a host-wide `revision`.
- **`claudeSessionId` for every followed session** in the welcome, `sessions.status` and `sessions.list`.
- **The WPF shell** attaches as an observer when Reframe runs on the profile, or as the primary with `--take-over`.
  Reframe itself does not use any of this; the shell is experimental and not part of the release package.

Windows x64 portable release; unsigned.
