# 0.11.0-claudegpt.113

Fixes from a QA pass over the shell, the Chat view and the task tools.

- **Delayed saves on the UI thread.** A delayed save (selected thread, sidebar width, window bounds) serialized the state on a timer thread while the UI thread changed it: a "collection was modified" crash or a torn state.json was possible. It is now serialized on the thread that owns the state.
- **Long transcripts in the Chat view.** The first read of a transcript loaded the whole file at once on the UI thread (hundreds of MB for a long thread). A read now takes at most the last 8 MB, from the first whole line in them.
- **Model sync after a fork or a new session** reads that session's transcript (the path was cached per thread, not per Claude session).
- **Scheduled tasks:** `update_task` and `delete_task` only act on the calling thread's own tasks (another thread's are listed by `list_tasks all` but refused); the user can still change any task under Tasks. `INTERVAL` and `COUNT` take one number, as the scheduler reads them (a list was accepted, then never ran).
- Tests: a long-transcript read, task ownership and the rule checks.
