# ClaudeGPT Reframe 0.10.1-claudegpt.29

**No early "done" when Reframe is attached to an older PTY host.** Release .28 holds "done" back while a claude
still has background tool shells running, but only hosts with `sessions` service version 2 apply that rule. A
Reframe attached to an older PTY host that kept running across the update (its `sessions` service is version 1)
still got idle and "done" at the end of every turn.

- With such a host, Reframe now applies the rule itself. When the host reports a session idle with a "done", Reframe
  looks for tool shells of that claude (the process id it already knows for the session). If there are any, the
  session shows **Idle, background work running** and the "done" is held back.
- Those sessions join Reframe's own recheck every 20 s. When the last tool shell is gone, the session becomes idle
  and the "done" notification comes then. A later busy, waiting or ended status from the host ends the wait as
  usual.
- Without a known process id, or for sessions in WSL, nothing changes. Hosts with `sessions` version 2 are
  unchanged.

Windows x64 portable release; unsigned.
