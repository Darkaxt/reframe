# 0.11.0-claudegpt.133

## The UI thread's stack when Reframe stops responding

- .132's watchdog showed long freezes: the UI thread did not respond for 300 s and then 110 s after a start, with
  thousands of terminal outputs waiting for it, and for one to four seconds now and then. Its "doing" was not to be
  trusted: a terminal snapshot's name stayed set over an await (two snapshots at once left it set for good). It is
  set only around the snapshot's output now.
- When the UI thread has not answered for 5 s, main.log gets its managed stack too (`ui: the UI thread's stack:`),
  read from a snapshot of the process with ClrMD (Microsoft.Diagnostics.Runtime, MIT), at most once in ten minutes.
  Only method names are logged. The library is loaded only then.
