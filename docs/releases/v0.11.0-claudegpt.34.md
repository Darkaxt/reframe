# ClaudeGPT Reframe 0.11.0-claudegpt.34

- **Faster start.** The managed launcher spent 3-4 seconds checking the release with nothing on screen before Reframe
  appeared. It now walks the release folder once and reuses the hashes of files unchanged since the last passing
  launch (`runtime\hash-stamps.json`; a changed file is hashed again): about 0.3 s, 1.6 s on a release's first start.
  Deploy and restore still hash everything.
- **The shell's log.** The native shell's diagnostics (session starts, notifications, takeovers, entry points) are
  written to the profile's `logs\main.log` again, in the Electron log's line format, with start and stop lines. A log
  past 5 MB at start is kept as `main.old.log`.
- **A tile's × works on the first click.** Pressing a tile's header button moved the focus into the terminal, which
  took the press away from the button: the click was often lost and the header flickered, and a second click could
  land on the tile that had moved into its place. A press on a button now stays with the button.
- **An ended session's dot is grey.** A session ended from its tile's × (or Terminate all) kept the last status the
  host had reported, so its dot could stay green. Only a session the host still runs now has a run status, and ending
  one updates its dot in every window.
- **An ended session reads "ended" in the sidebar.** A session whose tile still showed it was listed as "window 1"
  after it ended; it now reads "ended" (Electron showed the window number too).
- **"Restart terminal host" instead of "Claude Code could not be started".** The terminal host kept running across
  the update (so its sessions went on) can be one from before the native shell, which cannot start sessions for it:
  starting or resuming a session failed with "Claude Code could not be started". Such a session's card now says the
  terminal host is too old and offers **Restart terminal host**: after a confirmation it saves the state, ends the old
  host (its running sessions stop; conversations are kept), starts Reframe again through its launcher and quits; the
  new Reframe starts the current host and resumes the open sessions there.

The PTY host protocol, the profile and `state.json` are unchanged.
