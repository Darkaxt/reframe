# 0.11.0-claudegpt.124

## Cron jobs stay with their thread

- Claude Code keeps durable cron jobs (CronCreate) per folder, and the session holding the folder's scheduler lock
  runs the jobs whose own session has ended. A job of one thread could fire in another thread of the same folder,
  which then did that work as its own: the DualSouls thread ran the Aurral thread's production cutover.
- Reframe's per-session hooks now tag each job with the thread that creates it (PreToolUse, matcher CronCreate: a
  first line `[Reframe: a scheduled job of the thread <id>]`). The job is created as asked, durable or not, so
  watchdog ids stay valid.
- When a tagged job fires in another thread, the host blocks it there (UserPromptSubmit) and hands it to its own
  thread, which gets it as a scheduled task's run does: once idle, resumed first if it has ended. A job whose thread
  is gone shows as a run that could not be delivered.

### Limitations

- Sessions started outside Reframe have no such hooks: they can still run a Reframe thread's job.
- Jobs created before this release carry no tag and are not handed on.
