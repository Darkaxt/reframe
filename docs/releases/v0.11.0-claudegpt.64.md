# ClaudeGPT Reframe 0.11.0-claudegpt.64

- **A thread that ends with a large Windows exit code no longer freezes Reframe.** Exit codes such as `0xC000013A` (a closed or interrupted console) are above what a signed 32-bit number holds. Reading one threw, which silently stopped the shell reading from that pty host while the connection still looked open. Every terminal of the host froze, its service answers (quota, monitor, session list) never came, and `open_thread` requests were lost. On the next start, the same exited session in the host's welcome made the start fail with no window, and later launches handed over to that windowless process. Exit codes are now read as Windows shows them (negative for these).
- **One message the shell cannot handle no longer ends a host connection.** It is logged (`host: message … not handled`) and the reading goes on. If the reading does end, the connection is closed and its pending calls fail instead of waiting forever.
- **A host whose welcome cannot be read is skipped**, like one that does not answer, instead of failing the start.
- **A failed start says so and exits.** It shows the reason and writes it to `main.log`, instead of leaving a process with no window holding the profile.
- **`open_thread` and `wake_thread` report a request that nobody would open.** When no Reframe window is attached to the thread's host, the host refuses the request (HTTP 503) and the tool says nothing was opened. Before, it answered that Reframe was asked, and the host dropped the request.
