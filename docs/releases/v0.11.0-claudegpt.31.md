# ClaudeGPT Reframe 0.11.0-claudegpt.31

**The Windows app is now the native shell.** This is the first release in which `reframe.exe` is the native WPF shell
(`wpf/Reframe.Shell`) with the Rust PTY host (`rust/reframe-host`) instead of the Electron app. The PTY host protocol,
the profile folder and `state.json` are unchanged: the shell reads every Electron-written state and attaches to the
host that is already running, Node or Rust, so a hot swap keeps the running sessions (same claude processes, same
host). No Electron file ships; the package is self-contained (no .NET install needed). See `docs/wpf-cutover.md`.

What the shell brings over from the Electron app (stage 4 and the stages before it):

- **Sessions**: the New Session dialog (with model suggestions), resume, restart, start fresh, error tiles and the
  ended card, ending a tile or a whole group, and taking over a claude running in another terminal (from the list or
  by dropping its window on reframe).
- **Startup**: open sessions the host still runs are attached, never restarted; open sessions in a window that the
  host no longer runs are resumed through the normal Resume path (one running elsewhere waits for Take over); open
  sessions in no window are ended.
- **Layout and windows**: tiles, splits, groups, the dock, several windows, the tray (closing a window keeps its
  sessions), notifications, Settings, the chat history and its jobs, the activity overview and WSL sessions.
- **Managed release**: `--profile`/`REFRAME_USER_DATA`/`reframe-config.json` choose the profile as before; `--quit`
  quits keeping sessions, so `stop-managed.ps1 -KeepSessions` and the hot swap work unchanged; the Start menu
  shortcut, `Reframe.lnk` and the login entry are kept pointing at the running release. `reframe.exe`'s file version
  is the release version.

## Rollback to Electron

The cutover activation keeps `rollback.json` (the previous executable: the last Electron release,
0.10.1-claudegpt.30) and a frozen `restore-managed.ps1` in its receipt folder (`release-<version>\activation\`):

1. Quit the shell keeping sessions: `& (Get-Content D:\Tools\Reframe\active.json -Raw | ConvertFrom-Json).stopScript -ActivePath D:\Tools\Reframe\active.json -KeepSessions`.
2. Restore: `& <receipt>\restore-managed.ps1 -Receipt <receipt>\rollback.json -ReceiptSha256 <its sha256> -KeepSessions`.
3. It restarts through the launcher: Electron takes the live host's sessions over on the same profile.
4. If Start with Windows was on, toggle it in Electron's Settings (the entry points at the shell's release).

The rollback needs the Electron release's `releases\<v>` and `maintenance\<v>` folders unchanged; the deploy keeps them
until Electron is retired.

## Known gaps

- At startup the shell does not refuse sessions of another reframe's older host (`olderHost`), and does not end host
  sessions that are not open or not shown when it attaches.
- Claudes running inside WSL are not listed, so they cannot be taken over from the list; opening several running
  chats at once asks once per chat.
- A toast click while the shell is not running starts nothing (no `LocalServer32` registration).
- There is no portable data folder: a start without `--profile`, `REFRAME_USER_DATA` or `reframe-config.json` uses the
  shell's own test profile.
- The Android client listener is not part of the shell yet.
- Electron stays in the repository and CI (visual parity, conformance) until one stable week after the cutover.
