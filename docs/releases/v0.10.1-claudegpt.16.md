# ClaudeGPT Reframe 0.10.1-claudegpt.16

- Claude sessions now outlive Reframe: their terminals run in a PTY host of their own (Reframe's runtime run as Node,
  detached and hidden), and quitting Reframe, updating or deploying keeps them running by default.
  - The next Reframe attaches to the profile's host and takes its sessions over, same processes; the tiles redraw
    from the terminal mirrors. Hooks and the statusLine quota reach whichever Reframe is attached, also for sessions
    an earlier Reframe started.
  - The host is reached through a named pipe per profile, with a versioned handshake and a token file only the user
    can read. A host of another protocol version keeps serving its sessions (shown as run by an older host, with Take
    over) and exits after its last one.
  - An installed Reframe runs the host from a versioned copy (`<install>\ptyhost\<version>-<hash>`), so removing a
    release never removes a running host's files; copies no host runs any more are removed.
  - "End sessions and quit" in the tray menu ends the sessions with Reframe, as quitting did before. Logging off or
    shutting down Windows works as before; if the host itself dies, its sessions are lost and can be resumed, as
    before.
- Maintenance: `stop-managed.ps1 -KeepSessions` quits Reframe and leaves its PTY host and sessions running;
  `deploy-managed.ps1 -HotSwap` activates a release while they run, to be taken over by it.

Windows x64 portable release; unsigned.
