# 0.11.0-claudegpt.120

## Gemini threads run Google's Antigravity CLI

- A Gemini thread now runs Google's Antigravity CLI (`agy`) in its terminal. It replaces .119's route through the
  ClaudeGPT proxy, which never worked: the proxy has no Gemini backend. Install agy with
  `winget install Google.AntigravityCLI`, then run `agy` once to sign in. Without agy, the tile and New session say so.
- The models are agy's own ids, which include the effort: Gemini 4 Neon (xhigh, high), Gemini 4 Hydrogen xhigh,
  Gemini 4 Argon high and Gemini 3.8 Flash high. The permission modes map to agy's: bypass, accept edits, plan and auto.
- Status: the host follows agy through per-session hooks (SessionStart, PreInvocation, Stop), relayed by
  `reframe-host --agy-hook`. Each session writes its own `.agents` folder, passed with `--add-dir`. agy's global
  configuration is not touched.
- Thread tools: `open_thread`, `close_thread`, `wake_thread` and the scheduled tasks reach agy through the same
  per-session MCP configuration.
- agy picks its own conversation id. The thread adopts it when agy reports it, then resumes it with `--conversation`.
- The Chat view and the model chip read agy's transcript (`~/.gemini/antigravity-cli/brain/<id>/…/transcript_full.jsonl`):
  messages, answers, tool calls with their results, and the diffs of edits and writes.
- Gemini threads have their own workspace, `Documents\Gemini`. They run in Windows folders only.
- The proxy's running-thread count is back to ChatGPT threads only.

### Limitations

- agy reports no "waiting for permission" event, so a Gemini thread stuck at a permission prompt shows as busy.
