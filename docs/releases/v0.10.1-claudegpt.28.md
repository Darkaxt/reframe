# ClaudeGPT Reframe 0.10.1-claudegpt.28

**No "done" while background work is still running.** Claude Code can end its turn while it still has background
shells running, for example a Bash `run_in_background` task or a monitor. When one of them finishes, it starts a new
turn on its own. Reframe used to show such a session as ready and announce it as done.

- At the end of a turn, Reframe now looks for *tool shells* left running in that claude. These are direct children of
  the claude process named `bash.exe`, `sh.exe`, `pwsh.exe`, `powershell.exe` or `cmd.exe` that are at least 5 s old,
  so short-lived status line and hook commands do not count. MCP servers (`node.exe`) never count.
- If there are any, the session shows a status of its own, **Idle, background work running** (German: "Bereit,
  Hintergrundarbeit läuft"). In the sidebar and on the tile it has the busy colour, dimmed. Reframe sends no "done"
  notification yet.
- Only those sessions are looked at again, every 20 s. When the last tool shell is gone and Claude has not started a
  new turn, the session becomes plain idle and the "done" notification comes then.
- A new turn (a prompt, or Claude Code starting one itself) works as before, and so do the "needs you"
  notifications. Sessions in WSL are not checked and behave as before.

The rule is the same in the Rust and Node PTY hosts and in Reframe's own fallback. Each check is one toolhelp process
snapshot (a few milliseconds). The hosts' `sessions` service is now version 2: a status event carries
`background: true` with status `idle`. No protocol bump is needed. An older Reframe attached to a newer host shows the
session as idle and gets its "done" notification when the background work ends.

Windows x64 portable release; unsigned.
