# ClaudeGPT Reframe 0.10.1-claudegpt.14

- Clicking a "done" or "waiting" notification brings up its thread again: the window comes to the front, switches to
  the session's project and Single-view thread, expands the tile if it is docked and focuses it.
  - The notification object is now held until it is clicked, closed or replaced; before, it could be garbage-collected
    right after it was shown and its click handler went with it.
  - On Windows the toast carries the session in its activation arguments and is handled by
    `Notification.handleActivation`, so a click also works from Action Center.
- The managed build has a fixed app id (`Darkaxt.Reframe.<profile>`, set by the launcher) instead of the release
  folder's `reframe.exe` path, with a stable toast activator CLSID. On start, Reframe adds both to the Start menu
  shortcut "Reframe - <profile>" and to `Reframe.lnk` in the installation folder, keeping their target and arguments
  (the VBS launcher). If either is missing, Reframe creates it.
- If Electron's own Start menu shortcut (`reframe.lnk`) carries an older activator CLSID, it is removed so that
  Electron rewrites it with the current CLSID. When deploying, the installation folder gets a `Reframe.lnk` that
  runs the launcher, and a Start menu `reframe.lnk` that points straight into `releases\` is removed.

- Terminal keys and copying:
  - Shift+Enter in a terminal types a newline into the prompt (ESC CR, Claude Code's Meta+Enter) instead of sending
    the message.
  - Enter with text selected copies it and clears the selection, as in the Windows console; nothing is sent to the
    session. Ctrl+C, Ctrl+Shift+C and right-click copy as before.
  - Every copy shows a short notice over the terminal for about two seconds, e.g. `Copied "first 40 characters…"
    (N chars)`.
  - When the program reads the mouse (Claude Code's fullscreen mode), the first drag without Shift shows "Hold Shift
    to select text", once per session.
  - xterm itself still clears a selection on typed input, on a change of the terminal's height, on a switch to or
    from the alternate screen, and when the program turns mouse reporting on. Output that rewrites the selected
    lines changes the text under the selection.
- Terminals draw again after a GPU driver reset. A lost WebGL context drops to xterm's DOM renderer and the terminal
  is redrawn at once. WebGL is tried again after 3 s, or when the window comes back into view. After 3 losses that
  terminal stays on the DOM renderer. The main process logs a lost GPU process and tells every window to redraw
  its terminals.

Windows x64 portable release; unsigned.
