# ClaudeGPT Reframe 0.10.1-claudegpt.25

PTY host protocol additions for the experimental native WPF shell (`wpf/`), so that it can run beside Reframe. Both
hosts (Node and Rust) implement them, and the conformance tests hold both to them. The protocol version is unchanged
(1): everything is additive and advertised, so a hot swap keeps every running session.

- **Observers.** A client can attach read-only, beside the attached Reframe, without replacing it (`role: "observer"`
  in its hello; advertised as `services.observer: 1` in the welcome and `observer: 1` in the host descriptor). It sees
  the sessions, their spawns, exits and status changes, and can open terminal views of its own, which are
  **read-only**: the host ignores an observer's input and resizes, and its spawn, write, dispose and shutdown
  requests. Of the services it may only read (`sessions.list`, `observer.primary`, and the transcript list, info,
  times and title); other requests are refused with the new error code `forbidden`. `observer.primary` and an
  `observer.primary` event tell whether a primary client (Reframe) is attached. Replacing the primary no longer closes
  other connections' views.
- **Ordered session statuses.** `sessions.status` events and `sessions.list` now carry a `revision` from one counter
  in the host, so a client can tell an event that the list already holds from a newer one: it applies an event only
  when it is newer than the list and than what it applied for that session.
- **Claude Code's session id for every followed session.** The welcome's sessions, `sessions.status` and
  `sessions.list` carry `claudeSessionId`, also for sessions started without `meta.launched` (started directly): it
  is taken from the session's registry entry, else from its latest hook's `session_id`, else from what Reframe gave.
- **The WPF shell** attaches as an observer whenever it finds Reframe running on the profile and the host offers
  observers, instead of refusing; its terminals are then read-only. With `--take-over`, or with no other client
  there, it attaches as the primary as before. Against an older host (no observers) it behaves as before: it refuses
  while Reframe runs unless given `--take-over`. It applies the revision rule and uses `claudeSessionId` for titles.

Limits: an observer cannot type into a session, resize it, or start or end one; to do that the shell must take over
(which detaches Reframe, as before). The shell does not yet add sessions spawned after it attached to its list. A
session started by a Reframe before 0.10.1-claudegpt.22 (no `meta.claudeHome`) is not followed by the host's
`sessions` service, so it gets `claudeSessionId` only in the welcome, from its hooks. Reframe itself (Electron) does
not use any of this: it still attaches as the primary, and only tolerates the new fields. The WPF shell is
experimental and not part of the release package.

Windows x64 portable release; unsigned.
