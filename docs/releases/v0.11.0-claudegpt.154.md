# 0.11.0-claudegpt.154

Raised by the "Doodle Jump" thread while taking over a Gemini conversation: tools couldn't tell which agy process belonged to which conversation, couldn't remove a retired thread's tile, and couldn't read Reframe's name for a conversation.

- **Thread map.** Reframe keeps `<profile>\threads.json`, rewritten when anything in it changes (checked every 20 s). For each thread it lists:
  - `name` (as Reframe shows it), `id`, `provider`, `model` and `conversationId` (the Claude session or the agy conversation);
  - `pid` of the client while it runs, `status`, `lifecycle` and `folder`;
  - for a Gemini thread, `hookFolder`, the folder its agy runs in;
  - `openedBy`.

  A running client's `REFRAME_SESSION` environment variable is the thread's `id`, so any process maps to its conversation.
- **`list_threads`.** The new thread tool returns that map at once.
- **Ids as names.** `message_thread`, `read_thread` and `close_thread` take a thread's `id` or `conversationId` as the name. A retired conversation's tile can then be closed by its conversation id: `close_thread` with action archive or delete. A thread whose history files are already gone is only removed from Reframe.
- **Hook cleanup.** The hook files of threads Reframe no longer has (`hooks\<id>.json`, an agy thread's `hooks\<id>-agy` folder) are removed hourly once untouched for an hour. The profile had 1,180 of them.
