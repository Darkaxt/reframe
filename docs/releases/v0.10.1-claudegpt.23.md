# ClaudeGPT Reframe 0.10.1-claudegpt.23

- The PTY host now writes Reframe's state file (`state.json`) when it can (new `state` service, added to the host
  protocol without changing its version). The file, its format, its place and its backup (`state.json.bak`) stay
  exactly as before, so any Reframe release reads it. Writes are atomic (a temporary file, flushed to disk, then
  renamed over it) and carry a revision, so a writer that is out of date is refused instead of writing over newer
  changes; Reframe then reads the file again and writes its newest state. Checking the state and bringing older
  files up to date stays in Reframe. Without the service (an older host taken over in an update) or if the host
  cannot write, Reframe writes the file itself, as before; it still loads it itself, before the host is started.
  - The Rust host writes it with `rust/reframe-services`, the Node host with Reframe's own code; both are held to
    Reframe's in-process writing in tests.
- A burst of requests to the PTY host (the transcript times and titles Reframe asks for when it starts) now waits
  its turn instead of being refused with "too many transcript requests at once": up to 8 are worked on at once and
  64 more wait; only beyond that is a request refused.
- The tray menu has "Terminate all sessions" and "Quit" instead of "Quit Reframe (sessions keep running)" and "End
  sessions and quit". "Terminate all sessions" ends every running session the way a tile's × does (they stay in the
  session list and can be resumed) and keeps Reframe open; it is greyed out while no session runs. "Quit" quits as
  before, the sessions keep running for the next Reframe.
- The Claude quota below the session list shows again when Claude Code has a status line of its own (Reframe then
  cannot read the quota from its sessions): newer LLM Coordinators observe the Claude quota too, and Reframe now
  takes it from the same answer as the Codex quota. Reframe's own reading, when it has one, stays preferred; the
  Coordinator's is shown only when it was observed later.
- In the new session dialog (the + beside a workspace), switching the provider no longer replaces the folder with
  the other provider's workspace root: a folder inside the previous provider's root keeps its relative part under the
  new root, and any other folder stays as it is.

Windows x64 portable release; unsigned.
