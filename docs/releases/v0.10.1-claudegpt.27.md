# ClaudeGPT Reframe 0.10.1-claudegpt.27

**Hide threads from Reframe.** A Claude Code session you run elsewhere (for example in a plain terminal) can be hidden
from Reframe, so that it is not listed and Reframe never offers to take it over or resume it.

- **Hide from Reframe…** in the context menu of a session in the session list and history (German: "In Reframe
  ausblenden…"), after a short confirmation that says how to restore it. It acts on that one thread, keyed by its
  Claude session id (stable across resumes), not on its folder.
- A hidden thread is invisible to Reframe: it is not listed (running elsewhere, history, pinned, project folders, or a
  search), not offered for take-over, adoption or resume (also not when its terminal window is dragged or torn out
  over Reframe), not counted, and not notified about.
- Hiding only changes what Reframe shows. Reframe does not end, change or touch the session's process, its registry
  entry or its transcript.
- A session Reframe runs cannot be hidden while it runs ("Hide from Reframe (end chat first)"). An ended Reframe
  session that is hidden leaves the lists, but its record is kept, and nothing of its history or transcript is
  deleted: restoring it brings it back as it was.
- **Settings › Hidden threads** lists each hidden thread with its title (as it was when hidden), its folder and when
  it was hidden, with **Restore** for each and **Restore all**. A restored thread shows again at once, without a
  restart.

Hidden threads are kept in `state.json` (`hiddenThreads`); files from earlier versions load with none. They are
filtered by a set lookup where sessions are discovered: no extra polling and no extra transcript reads.

Windows x64 portable release; unsigned.
