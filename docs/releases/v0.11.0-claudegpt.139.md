# 0.11.0-claudegpt.139

The shell's startup, and what its UI thread does in a busy stall.

- The toast notifier (Windows' notification platform, in another process) is created off the UI thread. In .138 it held the UI thread up at startup. A toast shown before it is ready is shown once it is.
- A stall's stack sample now also gives the UI thread's managed frames as the process snapshot has them. The live native walk of a thread that is running can come out torn; the snapshot's is consistent, so busy stalls are named too.
- Every operation the UI thread's dispatcher runs now names itself while it runs: a timer by its Tick handlers, an async method's continuation by the method, anything else by its delegate's method. So a stall's "doing:" is never "-" any more; it names whatever held the UI thread. The existing labels inside operations stay as they are.
