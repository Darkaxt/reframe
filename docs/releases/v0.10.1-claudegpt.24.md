# ClaudeGPT Reframe 0.10.1-claudegpt.24

- Reframe now saves its state file (`state.json`) through the PTY host when the host offers the `state` service
  (added in 0.10.1-claudegpt.23); the file, its format, its backup and its place are unchanged. One write is under way
  at a time; saves made meanwhile are merged, and only the newest is written next. When the file was changed by
  something else, the host refuses the write; Reframe then reads it again and writes its newest state over it, so no
  save is lost.
- A save no longer has to be on disk when it returns. Reframe waits for the newest state to be written before it lets
  the host go on quitting, and before it reports a batch of chat operations (change model, archive, delete) as done.
- Reframe still writes the file itself, as before, whenever the host cannot: a host without the `state` service (for
  example an older host still running from before an update, which this Reframe takes over), a write that fails for
  any reason other than a refused one (logged as a warning), and on quitting when the host has not written within
  5 seconds. After such a timeout every later save of that run is written in-process.
- Loading the file, and its schema, stay in Reframe.

Limits: the end-to-end tests read the file after asking the running Reframe to finish its writes (a test hook), as
any outside reader must; a program other than Reframe reading `state.json` while Reframe runs may see it a moment
behind the window it shows. The protocol version is unchanged.

Windows x64 portable release; unsigned.
