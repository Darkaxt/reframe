# ClaudeGPT desktop fork

Reframe is the session manager; the separately maintained Claude CLI is patched by tweakcc-fixed/lobotomized-claude-code, and ChatGPT requests use the claude-code-proxy fork. Those are independent versioned components. This repository preserves upstream Reframe history and is integrated into the proxy project by a pinned source link. Keep the native executable selected in Settings.

New session lets you choose ChatGPT (the existing proxy/settings) or Anthropic (Claude subscription) and an optional model. End a chat before changing its Model provider in the context menu. The provider is retained across restarts; errors/refusals never switch it. Anthropic defaults to the native `sonnet` alias; choose a different Claude model in Advanced. Subscription login happens through Claude's native `/login` flow. Reframe does not read/store account tokens. Native trust, authentication and permission prompts remain native controls.

Folders are automatically catalogued from all managed and discovered histories. Select one to filter chats; New session uses that folder. This does not start or take over chats. Manually saved layout workspaces remain available. Provider icons identify known/selected routes; a question mark means an external history's provider has not been selected yet.

Archive chat creates a streamed, fully hash-verified ZIP with the exact transcript, owned subagents/session artifacts and matching history/index rows before retiring the live history through the installed exact-handle helper. Archived chats can be restored from the sidebar; restore never overwrites different live files. The original ZIP remains retained after restore. Settings → Chat archives selects a non-C destination. Do not unplug an archive drive during an operation. Errors retain the operation directory, verified ZIP if available, plan and exact residual receipt. For interrupted retirement, inspect that receipt; never delete the containing Claude project folder. A verified archive can be restored using the bundled backend's restore command with its recorded SHA256 and exact home/UUID, or the normal sidebar when activation completed.

Delete chat permanently retires the selected inactive history after confirmation. It does not create a backup. Both actions refuse running/external references and changed snapshots. End the chat yourself first; the app never stops work to obtain archival/deletion clearance. Source repositories, settings, credentials, skills, shared memory, other chats and ImageGen outputs are excluded.

## Windows helper bindings

Archive/delete use the installed `thread-cleanup` helper and its activated `transactional-cleanup` filesystem runtime. Configure explicit `REFRAME_HISTORY_PYTHON` (absolute Python executable), `REFRAME_HISTORY_HELPER` (installed invoke_thread_cleanup.py), and `REFRAME_HISTORY_HELPER_SHA256` after reviewing that source. Unknown/missing helper versions fail closed. The backend is included in the portable package and runs with Python `-I -B`. Keep process TEMP/TMP and optional REFRAME_RUNTIME on explicit persistent D: storage. No shell command comes from a transcript. This desktop fork's managed archive/delete backend currently requires Windows; ordinary Reframe functionality retains upstream platforms.

Pinned dependencies: `maintenance/build-windows.ps1 -Mode Install -Scratch <exact-D-task-scratch>` uses npm ci with lifecycle scripts disabled. After whole-scope source readiness, Validate runs type/lint/tests/build, and Package produces the Windows portable ZIP without publishing. Native Electron is the exact locked package; no CLI/proxy repatching is involved. Private qualification, account data, archive contents and activation receipts must never be committed or uploaded.

Publication uses the Darkaxt/reframe release, verified tag/source commit, portable ZIP and SHA256. Integrate the exact fork commit in the proxy project's GUI source reference. Preserve the installed prior version and frozen launcher/state recovery at cutover; activate only after observed idle/owned exits and verify the normal GUI and protected files. Never replace the fork with a stock-updater release.

## Managed activation and recovery

`maintenance/windows/deploy-managed.ps1 -Manifest <private-json> -ManifestSha256 <sha256>` consumes the reviewed `claudegpt.reframe-deploy.v1` contract. It checks the qualified candidate's complete file list, ZIP, exact source commit, qualification and independently retrieved release receipts; current active record, protected files, installed helper and a candidate-bound idle reservation. The reservation records that clients are closed, Goal/background producers are paused, and they will stay idle until delivery verification. A fresh native process scan rejects any remaining Reframe/Claude client or Claude Node/Bun wrapper. Enabled Task Scheduler request producers require separate resolution before cutover. Native app automations are covered by the explicit reservation, not inferred from a quiet process or monitor. No client is stopped by the deployer.

The private manifest binds the SHA256 of every release script, candidate/qualification/delivery/idle receipt, prior active record, protected files, managed CLI active record path and all exact installation/evidence paths. Keep the JSON and owner/process evidence outside Git; it contains machine-specific paths. Required path fields are `activePath`, `launcherPath` (existing PS shim behind the VBS shortcut), new `launcherDirectory`, new `releaseDirectory`, new `receiptDirectory`, `managedActive`, `claudeHome`, `workingDirectory`. `scripts` contains `{file,sha256}` entries; `protected` contains `{path,sha256}`. Qualification must mark `chatgpt`, `anthropic`, `packaged`, `history`, `payload` true and bind `archiveSha256`. Delivery binds `sourceCommit`, `archiveSha256`, `retrievedVerified`. The candidate keeps `files`, exact helper/Python bindings and final `qualified` status. Missing checks leave live pointers intact.

The deployer freezes the prior active pointer, PS launcher and durable state/state backup after clients exit, retains the complete prior release, and installs a new versioned payload and launch scripts without overwriting an existing release. It writes an activation journal and one `rollback.json` plus frozen restore implementation before changing live pointers. The existing VBS shortcut remains; the process-only launcher verifies app/helper/CLI provenance, keeps the default native account/MCP binding, uses persistent D: runtime storage, and opens the requested GUI normally. Launcher/installer exit records only `verification_pending`. Independently verify actual process start identity/path, normal GUI, version/payload hashes, provider settings/protected files and one benign request before setting installed status verified.

For cutover failure, use the exact activation's frozen `restore-managed.ps1 -Receipt <rollback.json> -ReceiptSha256 <recorded-hash>` after the new GUI and owned children exit normally. It refuses live clients, validates the entire prior payload/protected/recovery set before restoring, restores pointer/launcher/state atomically per file, and restarts through the original quiet VBS. Independently verify the original GUI/process/hash and service operation; its exit alone does not prove recovery. A synchronous cutover failure restores automatically only when no client exists; otherwise its failure receipt states that owned idle or repair is required. Do not use this initial-cutover snapshot to overwrite later user work: review intervening state and retain it before any later recovery. Never delete a release, failed activation or recovery dependency to make a rerun succeed.

`test-release-files.ps1 -Scratch <new-exact-D-task-folder>` verifies package copying, atomic pointer replacement and complete frozen restore with fictional bytes, including corrupt recovery/path/extra-file/changed-input failures. It never bypasses production idle checks or launches clients. Retire fixture output through transactional-cleanup after inspecting its result. An unchanged application payload need not be rebuilt for deployment-script or documentation changes.
